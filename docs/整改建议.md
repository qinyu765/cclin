一、项目架构与配置管理优化
针对项目当前存在的配置分散、格式单一及兼容性不足的问题，会议提出了以下改进方向：
1. 配置存储与格式规范
集中化配置管理：指出当前将配置文件置于项目仓库内的做法存在安全隐患，建议参考 Claude 或 Cursor 的方案，将配置文件统一存储在用户根目录（如 `.claude` 或 `.cursor`），并在程序初始化时引导用户配置。
配置格式升级：鉴于 `.env` 文件缺乏嵌套结构无法满足复杂配置需求，建议迁移至 JSON 或 YAML 格式，以支持更复杂的层级关系与数据结构。
2. 多模型 API 兼容性
Provider 抽象层缺失：目前仅支持 OpenAI 兼容接口，缺乏对 Gemini、Anthropic 等主流模型的原生支持。建议引入 Provider 概念，实现 API 格式的统一兼容。
多模态能力补齐：尽管模型支持度不一，但必须在前端交互层（TUI）实现多模态输入（如图片粘贴），并在后端接口层适配多模态消息格式（Content 数组包含文件/URL）。
二、核心功能与交互体验缺陷修复
会议详细审查了系统的提示词管理、上下文控制及 TUI 交互细节，指出了多处功能缺失：
1. 提示词与上下文管理
系统提示词（System Prompt）优化：批评当前提示词过于简短，建议参考 Claude 官方或开源仓库（如 1000 行以上的提示词），增加角色定位、约束条件、工具使用说明及示例，以提升模型表现。
上下文防爆策略：指出仅靠 Token 计算和压缩（Summarize）不足以防止上下文暴涨，建议在工具设计层面增加细粒度控制（如文件读取的 Offset/Limit），并兼容 `.gitignore` 规则来自动排除无关文件。
2. TUI 交互体验缺陷
输入框功能缺失：当前输入框不支持手动换行（仅支持粘贴换行）及上下移动光标，导致长文本编辑体验极差，需修复。
清空输入逻辑缺失：缺乏类似 Cursor（Ctrl+C）或 Claude（ESC）的清空输入快捷键，需补充此类基础交互功能。
三、面试策略与职业发展建议
针对项目在简历包装及面试中的表现，会议从技术深度、差异化竞争及简历撰写三个维度进行了指导：
1. 技术深度与真实性
杜绝 Web Coding 印象：强调必须区分 AI Coding（懂原理、写 Prompt）与 Web Coding（盲目生成），要求对项目中的每一个技术点（如上下文压缩算法）都能讲清原理，避免被质疑项目真实性。
参考行业标杆源码：推荐阅读 Claude Code 泄露源码或社区解读，了解其架构设计与功能实现，以便在面试中能深入阐述 Agent 的核心概念（如 SubAgent、Workflow）。
2. 差异化竞争与简历包装
垂直领域深耕：建议跳出通用 Agent 的红海竞争，转向垂直领域（如法律分析、医疗影像诊断、手机操作等），通过解决特定场景问题来建立差异化优势。
简历撰写技巧：强调简历项目描述应重点突出“解决了什么问题”和“具备什么能力”，而非单纯罗列技术栈。建议完善 README 文档，增加演示视频，并利用博客（如 MCP 集成博客）展示技术热情。
